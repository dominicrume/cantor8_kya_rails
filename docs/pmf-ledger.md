# Pull ledger: the evidence a script cannot see

`python3 tools/pmf_check.py` reads public counts and says whether there is any outside pull.
It cannot see people. Product-market fit is people who would be very disappointed if this went
away, so those people are written down here, by hand, one row each, with a link and a date.

No row without a link and a date. No name without that person's permission. Nobody counts
who was asked to say something kind: a row is someone who used it on their own work.

## The question

Ask each person once, in these words, and write down the answer exactly:

> How would you feel if you could no longer use this? Very disappointed, somewhat
> disappointed, or not disappointed?

Fit is a pattern across many people, not one kind word. The usual bar is 40 per cent of the
people who have really used it answering "very disappointed". With fewer than 10 users there is
no percentage worth quoting, so this ledger says how many there are and stops there.

## The test, 23 November to 23 December 2026

Written before it starts, so it cannot be moved afterwards.

| What pull looks like | Where it is measured | Met by 23 December? |
|---|---|---|
| An outside repository imports `knowyouragenticai-receipts` | an authenticated GitHub code search, entered here | not yet |
| Three teams outside this project run the guard review or the skill on their own code and tell us | rows below | not yet |
| One named buyer signs, pays, or writes a letter of intent for a countersigned record | rows below | not yet |

If none is met by 23 December, the conclusion is that the offer is wrong, not that more needs
building. Change the offer, the buyer or the wording, and run a second 30 days.

## What each row is also for

A row with a name, a date, a link and what changed is a proof story. The same row is evidence
for an application that asks who recognises the work, so it is worth writing carefully once.
