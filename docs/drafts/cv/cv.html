Summary

I build Daml on Canton and treat every claim about it as something a stranger must be able to reproduce with one command. My current work puts the auditor on the signatory line, so a node holding one compromised key cannot create the contract at all, and proves that the ledger enforces its spending rules rather than the application. Every stated number in my repository is re-derived by a lint from the file that produces it, and every harness runs a deliberately broken control first, because a harness that can only report success cannot tell you whether it ran.

Verify this in two minutes

git clone https://github.com/dominicrume/cantor8_kya_rails
cd cantor8_kya_rails && python3 tools/prove_refusal_on_sandbox.py

Builds the Daml, starts a real Canton participant, sequencer and mediator locally. Runs a script that does not exist and requires it to fail. Only then runs the real one: Canton refuses a 90.0 charge against a mandate with 40.0 already spent, writes a refusal record naming the rule, and leaves the spent total untouched. If the control passes, the tool refuses to report anything. It also prints what it does not prove: single-participant local Canton, no Amulet, so nothing about a shared network or Canton Coin.

Technical evidence

  • Daml and multi-party authorization. 167 Daml files and 173 passing Daml Script tests across two packages. Guardian on the signatory line rather than the observer line: a create needs every signatory's authority, so a node holding one compromised key cannot bring the contract into existence. Propose and accept workflow, interfaces, and a package vetted on Canton DevNet under Canton's smart contract upgrade check.
  • Stating the limits of my own design. A named test proves the guardian pattern does not gate an owner-controlled consuming choice, because such a choice archives on the controller's authority alone. That is a specification hole and it is written into the file by its author rather than left for a reviewer to discover.
  • Adversarial testing. All 32 Daml fences are deleted in turn, the package is rebuilt, and a named test must go red, so no assertion is decoration. A wider suite breaks 82 real things the same way. The same harness, run on two OpenZeppelin Canton packages at pinned commits, found 49 of 62 fences with no test that failed when the fence was made vacuous. That is a coverage finding and not a vulnerability, and it was reported as public issues.
  • Privacy boundaries. A privacy matrix test asserts what each party can and cannot see, checked against the Daml rather than documented beside it.
  • Cross-implementation conformance. One receipt format, three independent implementations in Python, JavaScript and Go, graded against 20 shared vectors through a pipe.
  • AI-native engineering, held to a reviewable standard. Over 270 commits produced with Claude Code as a daily driver, governed by gates I wrote: a tool that refuses a quote that is not in a source file or an employer claim with no link, a tool that reads a destination back after posting instead of trusting a keystroke, and a lint that re-derives every stated count from its source file. An audit of my own repository found six wrong numbers, including a README that said 30 fences when the file had 32. My gates had passed all six, so I fixed the gates.
